{{- if .Values.nodeProfiles.install.enabled }}
Node profiles (mode: {{ .Values.nodeProfiles.install.mode | default "install" }}):
  DaemonSet 'node-profiles' in the dedicated {{ .Values.nodeProfiles.install.namespace }}
  namespace installs the browser seccomp/AppArmor Localhost profiles on
  Linux worker nodes (privileged initContainer + caps-dropped uid-0
  verifier — uid 0 is required to read the host's AppArmor loaded list).
  Watch rollout:
    kubectl -n {{ .Values.nodeProfiles.install.namespace }} get ds node-profiles
  A browser pod scheduled before its node reports ready fails boot and is
  retried — gate browser rollouts on DS readiness.

Reminder:
  * CRDs in crds/ are installed/never deleted by Helm. Upgrading CRDs is a
    manual step — see docs/runbooks/install.md.
  * All Secrets are referenced by name only; create them BEFORE the pods
    can start (see install.md "Secrets") unless certManager.enabled covers
    the internal mTLS Secrets.
  * `helm uninstall` keeps the managed namespaces, user PVCs and CRDs.
