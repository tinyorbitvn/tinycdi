# TinyCDI v0.3.0 — release notes

v0.3 "Operate": template update policies, control-plane availability,
observability, safer sessions and a real Linux desktop.
Merged since v0.2.0: #26–#29, #34, #38, #41–#76.

## What is new

**Templates and images**

- Template families with an update policy: `lifecycle.imageUpdate:
  OnStart | Pinned` (default OnStart). A stopped workspace moves to the
  newest compatible revision of its family when it starts; the detail
  page shows "Starts on the updated image" (#46, #56).
- Compatibility guard: a start does not move a workspace when the
  runtime, experience, data policy or disk size would change; the
  `TemplateUpdateSkipped` event says why (#56). The operator re-records
  the template snapshot when a workspace moves to a new revision (#56).
- Stale-image block (rc.2): a catalog revision older than
  `-image-block-after` (45 d default) refuses create/start with
  `409 IMAGE_STALE` naming the template; pinned workspaces get the
  fresh-image hint. The template view reports both browser engines via
  the `image-chromium`/`image-firefox` annotations (#64).
- Desktop profile: the Linux desktop is now XFCE (panel, menu, Thunar,
  terminal, Firefox) on a shared `linux-base` image, with Noto fonts
  for Vietnamese, WenQuanYi for Chinese/Japanese/Korean and Noto Sans
  Mono for terminals (#38, #51, #62).
- Kasm browser gate: a Kasm image used as a Browser may lag the native
  browser by at most two major versions; Browser templates must be on
  `kasmAdapter.browserAllowlist` (empty by default) (#63).
- Runtime-image `rt-*` tags now count successful publishes only — failed
  builds and scan rejections leave no gaps in the day's series (#65).
  The deprecated v0.1 `templates[].nodeSelector` annotation path fails
  the chart render — use `spec.placement.nodeSelector` (#67).

**Operations**

- Operator runs two replicas with leader election; PodDisruptionBudgets
  for operator and frontend; surge-first frontend rollouts (#44).
- mTLS material reloads without a restart: the operator client
  certificate, the operator's trust of the internal listener CA, and the
  internal listener's client CA (#45, FX-R33).
- Application rate limits on sign-in, session probe and launch, keyed by
  client address behind trusted proxies (`backend.trustedProxies`);
  client-sent forwarding headers never reach a workspace (#47).
  Authenticated requests key per validated session (probe, launch) or
  per validated OIDC state (callback, bounded by a 10× per-IP ceiling),
  so users behind one NAT keep per-user budgets — only the anonymous
  sign-in start shares the IP bucket (#75). Buckets are in-memory per
  replica: `backend.replicas` × the configured rate bounds a key's
  aggregate budget — size `-login-rate` as aggregate-need ÷ replicas.
- Metrics: HTTP by listener/route/method/code, active sessions,
  rehydrations, fenced streams, sign-ins, image age, rate limiting (#54).
  Opt-in Grafana dashboards and six PrometheusRule alerts
  (`dashboards.enabled`, `alerts.enabled`, `alerts.sessionDropFloor`)
  (#58).
- Database outage behaviour measured and documented: a 10 s outage keeps
  streams; a longer one closes them after about 30 s; the API answers
  503 UNAVAILABLE quickly instead of hanging (#57).
- Backend pre-stop drain: readiness drops at once, both listeners keep
  serving reads for the drain window (8 s), and only new launches and
  new stream upgrades get a retryable 503 — the hold applies to
  app-only backends too (#55, #68).
- Quota: a refusal caused by a workspace that is still shutting down is
  marked `release_pending` with Retry-After; reservations settle on the
  observed runtime absence instead of a 30 s tick (#42, #52). Loop
  hardening and one shared template resolver (#43, #52).
- Quota admin API and page (rc.3): `GET`/`PUT
  /v1/admin/tenants/{tenant}/quota` for tenant administrators, with
  `If-Match` optimistic concurrency — a stale version answers
  `412 PRECONDITION_FAILED`; tenants declared in values stay
  config-managed (`409 QUOTA_MANAGED_BY_CONFIG`, read-only in the
  portal) (#72).
- Purge path fixes: the sweeper patches finalizers within its own RBAC
  and tolerates a PVC that vanished mid-purge; the retained-data list
  refreshes after a purge (#70, #74).
- Capacity (rc.2 soak, #71): **60 sessions × 60 min** on the reference
  cluster (three infra workers, `soak-small` profile, 20 users) — zero
  dropped sessions, zero manual actions, connect p50 6.1 s / p95 7.4 s,
  input dispatch p95 89 ms. ~60 sessions is the safe level under the
  20 % CPU-request headroom rule; **200 sessions need ~50 CPU of spare
  requests** on the workload pool — the limiter is node CPU *requests*,
  not measured load (~36 mCPU per soak pod). See
  `docs/runbooks/capacity.md`.
- Soak (rc.3 + rc.4, #79, FX-R32): **60 sessions** on the reference
  cluster (three infra workers, `soak-small`, 20 OIDC lanes, default
  rate limits). rc.3 60 × 60 min: connect p95 6.3 s, dropped 0,
  falseElsewhere 0, but the all-pods backend rollout left a reconnect
  tail p95 39.9 s / p100 45 s — iframe re-navigation thrash aborted
  nearly-landed claims at fleet scale (failed the ≤10 s/≤30 s gates).
  rc.4 60 × 30 min after FX-R32 (in-frame reconnect): rollout spans p50
  ~5 s / p95 ~15 s / p100 ~15.0 s across 38 observed spans, zero
  relaunches (lease ids and `stream_owner_tab` unchanged on all 60
  leases — the tab id is outer-page-scoped, so that measurement could
  not see frame navigations), zero launch tickets minted, dropped 0,
  falseElsewhere 0, inputResume p100 23.3 s, gap p100 15 s (all spans at
  the harness's 5 s poll resolution) — p95 lands at ~15 s, still over
  the 10 s bar but ~3× better and the tail is bounded retry, not
  thrash. rc.5 targeted rerun: during an operator-initiated full
  2-replica backend rollout at 60 sessions, reconnect p50 **1.0 s** /
  p95 **15.0 s** / max **16 s** (1 s resolution); ~60 % resume in-frame
  in ~1 s, the rest via one frame reload; 0 dropped, 0 false elsewhere,
  0 new launch tickets. p95 still fails ≤ 10 s; p100 ≤ 30 s, input
  resume and gap gates all pass. mTLS
  drill (rc.3): operator client cert + internal CA rotated under 6 live
  sessions — streams survived, the backend hot-reloaded its server cert
  and client CA, and the old client cert was refused; **but the drill
  did not cover the operator's server-trust path**: the broker client
  read its CA bundle once, so it could not verify the rotated internal
  server cert and workspace deletes wedged in the runtime-cleanup
  finalizer ~4 h until an operator restart (rc.4 STEP-0 finding).
  FX-R33 (#83) closes it — verified in the **rc.5 re-drill**: both
  operator replicas logged `tlsreload: reloaded CA bundle`, 6/6
  sessions stayed connected, and 3 workspace deletes cleared the
  finalizer in 2.9 s **without an operator restart**. Details:
  `docs/runbooks/capacity.md`.

**Sessions and portal**

- Lifecycle progress: create, start, stop, delete and attach show their
  steps with plain-language reasons and elapsed time (#34, #61).
- Session robustness: early reloads resume instead of taking over; a
  stale tab offers "Use here"; foreign streams are detected
  conservatively (#48, #59). Clipboard permissions in the embedded
  frame follow the template's clipboard policy (#48, #55).
- Per-tab stream ownership: the lease records which portal tab claimed
  the stream, so a same-tab reclaim after a backend rollout resumes
  instead of showing "open in another tab" — and the ~2 min `none` gap
  that false elsewhere-verdicts caused during rollouts is gone (#76).
- Sign-out sends `id_token_hint` (sealed in the session store) so the
  identity provider skips its confirmation page (#55); the quickstart
  post-logout redirect was fixed (#69).
- Vietnamese UI (rc.3): full `vi` catalog with an in-app language
  switch, persisted per browser; dates/numbers format via `Intl`; key
  parity between the `en`/`vi` catalogs is enforced in CI (#73).

**Adoption**

- Quickstart on kind, a preflight script (incl. AppArmor detection),
  AppArmor RuntimeDefault as a cluster setting
  (`runtime.appArmor.requireRuntimeDefault`), host-network gateway
  policy tests, explicit rendering of API-defaulted fields so GitOps
  tools show no drift (#26–#29, #50, #53).
- Docs: branding, observability, tenant quotas, ArgoCD schema-cache
  note for CRD changes, sandboxed-runtime compatibility (#60).

## Upgrading from v0.2.0

The full procedure is `docs/runbooks/upgrade.md` ("Upgrading from v0.2
to v0.3"). The short version:

- **Back up the database first** (`pg_dump`). Migrations 015 (sealed ID
  token on sessions), 016 (clipboard policy on launch tickets), 017
  (`sessions.csrf_token` drops `NOT NULL` — the column itself drops in
  v0.4) and 018 (per-tab stream ownership on leases) are forward-only
  and additive.
- **Apply the CRDs first** — Workspace/WorkspaceTemplate gain
  `lifecycle.imageUpdate` and a widened `templateRef` CEL rule. Argo CD
  may show OutOfSync until its schema cache refreshes.
- **Set `backend.trustedProxies`** to your ingress/gateway addresses,
  otherwise every user behind one edge shares the anonymous rate-limit
  bucket (the backend logs a warning at startup).
- **Kasm Browser templates** fail to render until their image is on
  `kasmAdapter.browserAllowlist` or the template is re-classed as a
  Desktop experience.
- **Move legacy `templates[].nodeSelector`** entries to
  `templates[].spec.placement.nodeSelector` — the old field fails the
  render.
- The operator now runs two replicas with a PDB by default; the
  frontend PDB is on by default.
- Nodes without AppArmor need `runtime.appArmor.requireRuntimeDefault:
  false`.
- GitOps users: drop any `ignoreDifferences` you kept for HTTPRoute
  `matches` or `spec.linux.adapter`.
- Sessions survive the upgrade: streams on a rolling backend pod
  reconnect to a sibling inside the live lease.

## Known limitations

- Not independently security-reviewed; a full review is planned before
  v1.0.
- Sandboxed runtimes (gVisor/Kata) are untested; `runtimeClassName` is
  passed through.
- Per-user session limits were not exercised by the soak: the rc.2 run
  drove 60 sessions across 20 users (3 sessions per user), and the API
  has no per-user limit store (`userLimits` is absent — quota is
  tenant-scoped), so nothing per-user was configured or reached.
- Server-originated event and reason strings are English only; the
  Vietnamese catalog covers the portal UI (#73).
- Reconnect tail after a full backend rollout (p95 ~15 s at 60
  sessions, measured at 1 s poll resolution) — improvement tracked for
  v0.3.1.
- Workspace pods are not spread across nodes by default — a template
  carries only its `nodeSelector`; placement/anti-affinity is the
  operator's to set (`docs/runbooks/capacity.md`).
