# TinyCDI 1.0.2

TinyCDI 1.0.2 is a bug-fix release. Closing a session tab now frees the
workspace, so opening it again no longer asks you to take over. The
workspace list count reads correctly for one workspace, and the browser
image carries a Debian security update of Chromium.

## Changes

### Closing a session tab frees the workspace

In 1.0.1 the gateway kept renewing the connection lease of a closed
session tab until the portal session ended. Opening the workspace again
showed "This workspace is open somewhere else", and only "Take over
session" got in.

The gateway now ends a session that has had no stream, request, upgrade
or file transfer for the idle window (`backend.idleSessionRelease`,
default `60s`) and releases its lease. With the default, the workspace
can be opened again without the take-over dialog at most about 70 s
after the last stream closes when the replica that served the stream
releases it, and at most about 100 s in every other case. A running file
transfer keeps the lease. A reconnect inside the window, such as a
network blip or a rolling restart, keeps the session.

If you open the workspace again inside that window, the dialog still
appears. Its text now says that a tab closed in the last minute or two
can still be releasing the workspace; wait a minute, or take over.

- New chart value `backend.idleSessionRelease` (default `60s`; `0`
  turns the release off and keeps the 1.0.1 behaviour). Backend flag
  `-idle-session-release` / `TCDI_IDLE_SESSION_RELEASE`.
- New metric `tinycdi_gateway_idle_release_total{result}`, with `result`
  one of `released`, `refused`, `lapsed` or `error`. See the
  [observability runbook](../runbooks/observability.md).

### Portal

- The workspace list says "1 workspace" instead of "1 workspaces".

### Browser image

- Chromium is repinned to `155.0.8059.79-1~deb12u1`, the current Debian
  bookworm security update. The previous pin is no longer published, so
  the image could not be rebuilt.

## Upgrade from 1.0.1

1.0.2 has no database migration and no CRD change. It adds one chart
value with a default. Upgrade in place:

```bash
helm upgrade tinycdi oci://ghcr.io/tinyorbitvn/charts/tinycdi --version 1.0.2 \
  -n tinycdi-system -f my-values.yaml
```

If you raised the lease renew interval above 60 s (`-renew-interval` or
`TCDI_RENEW_INTERVAL` through extra arguments or environment), set
`backend.idleSessionRelease` to at least that interval, or to `0`.
Otherwise the backend refuses to start because the idle window must not
be shorter than the renew interval.

Verify the images with the `cosign verify` command in
[provenance.md](../security/provenance.md#verification-side-what-a-consumer-runs)
before you deploy.
