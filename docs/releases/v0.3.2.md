# TinyCDI v0.3.2 — release notes

v0.3.2 is a patch release on v0.3.1: chart additions for backend host
aliases and per-route Gateway listeners, a runtime manifest that
records the browser versions the signed images actually installed, and
test-harness hardening. Merged since v0.3.1: #95, #99, #103, #104,
#106, #108. No database schema, public API or CRD changes.

## What is new

**Chart values**

- `backend.hostAliases` (CHART-2): renders `spec.hostAliases` on the
  backend Deployment — extra `/etc/hosts` entries in the backend pods,
  e.g. resolving an in-cluster OIDC issuer host to a Service ClusterIP
  when cluster DNS cannot. Empty by default; empty renders nothing
  (#95).
- `gatewayApi.portalParentRefs` / `gatewayApi.sessionParentRefs`
  (CHART-2): per-route `parentRefs` overrides — a non-empty list
  REPLACES the shared `gatewayApi.parentRefs` for that HTTPRoute (the
  portal host vs the wildcard `*.<sessionDomain>` route), e.g. two
  listeners on one Gateway (`cdi-https` for the portal host,
  `wildcard-https` for the session domain). Empty falls back to the
  shared list, so a shared-only values file renders byte-identically
  to v0.3.1; with per-route lists on both routes the shared list may
  be left empty. The SEC-35 invariant now applies to the resolved
  per-route lists too — every parentRef, shared or per-route, must pin
  a `sectionName` naming a TLS listener (#95).

**Runtime manifest**

- `runtime-images.json` now records the browser versions the images
  actually installed (RTJSON-1): the `chromium`/`firefox` fields on
  `browser` and `firefox` on `linux-desktop` are read out of each
  image's attested SPDX SBOM at publish time — the full Debian package
  version `dpkg-query` would report (e.g. `154.0.8037.92-1~deb12u1`),
  not the Dockerfile pin that requested it (previously recorded with
  the Debian revision stripped, e.g. `154.0.8037.92`). The writer
  fails closed: a missing SBOM, no matching package, or more than one
  distinct version for the package aborts the manifest rather than
  guessing, and the lookup keys on the exact package name —
  `chromium-sandbox`/`chromium-common` never satisfy the `chromium`
  query. These fields feed `images.<key>.engines.chromium`/`.firefox`
  on the GitOps bump, so the stale-image annotations will carry the
  full package version (#99).

## Tests and docs

- SessionPage flake fix (FLAKE4): the restart/reconnect specs no
  longer race the render — the "Connected" assertion retries through
  `waitFor` instead of a single `findByRole` read, the frame reload is
  observed on iframe `src`-write counts rather than a DOM attribute
  poll, and a new spec pins the claim-evidence deferral: a stream loss
  whose epoch already advanced under our own tab id defers
  re-navigation and never reads "open in another tab". Tests only
  (#103).
- Soak harness reload check (A2-SOAKMETRIC): a reloaded session whose
  60 s post-reload window held zero observations now reports
  `reloadEvidence: "none"` — an explicit no-evidence verdict that
  lands in the run's `failures` instead of passing silently (it was
  previously just `seamless: false`, `reconnectMs: null`).
  `reloadEvidence` is `"observed"`/`"none"`, `null` when the session
  was never reloaded, and is in the report schema. Harness and tests
  only (#104).
- ADR 0006 — rate-limiter state placement (B4-LIMITNOTE): a design
  note pricing where limiter state should live in v0.4 — (A) keep
  divide-by-replicas and pin the divisor, (B) Postgres-backed windows
  for the login family and launch, (C) a hybrid local bucket with
  periodic Postgres sync — including the gaps the RL-1 model leaves
  (rolling-surge overshoot, stale divisor on out-of-band scale, and
  under-limiting by N when an ingress pins a client to one pod). The
  decision is made: option B — Postgres-backed windows for the login
  family and launch, failing open into the divided local limiter,
  which also stays as a per-replica ceiling. The implementation lands
  in v0.4; nothing changes behaviour in v0.3.2 (#106).
- Go native fuzz targets (B6-FUZZ): five stdlib `testing.F` targets on
  the auth/session parsing boundaries — `FuzzCallbackParsing` (OIDC
  callback params, login-cookie open, code exchange), `FuzzDomainMatch`
  (session-domain `ParseDomain`/`Match`), `FuzzHostClassify` and
  `FuzzLaunchRedeem` (gateway Host classification, launch-ticket
  redemption), and `FuzzClientKey` (trusted-proxy client-address
  derivation) — with checked-in `testdata/fuzz/` seed corpora that also
  run under the plain `go test` job. A dedicated, non-required `go
  fuzz` CI job runs each target 30 s on PRs touching the fuzzed
  packages (path-gated) and 10 m on the weekly schedule, uploading
  crashers as artifacts; 10 m local runs found 0 crashers. Tests and
  CI only (#108).

## Upgrading from v0.3.1

The procedure is `docs/runbooks/upgrade.md`. No migration, no CRD or
public-API change — a helm upgrade with the new chart is enough.

- New values default to the previous render — no action needed:
  `backend.hostAliases` and `gatewayApi.portalParentRefs` /
  `.sessionParentRefs` all default to `[]`; empty hostAliases renders
  nothing and empty per-route lists fall back to the shared
  `gatewayApi.parentRefs`, so an unchanged values file renders
  byte-identically (#95).
- The runtime release train's `runtime-images.json` `chromium`/
  `firefox` fields now carry the full Debian package version — a
  GitOps bump copying them into `images.<key>.engines.*` will set the
  revisioned form (e.g. `154.0.8037.92-1~deb12u1`) on the template
  annotations where v0.3.1 showed the bare engine version. Display
  only (#99).

## Known limitations

- Not independently security-reviewed; a full review is planned before
  v1.0. The review-prep material — threat model and security test
  inventory — lives in `docs/security/`.
- Sandboxed runtimes: gVisor verified on kind (desktop/terminal;
  Firefox ESR does not start under runsc — its WASM in-process
  sandbox's segue setup is unimplemented and the process aborts
  ~7–13 s in, while the desktop session itself stays healthy); Kata
  untested. `kubectl port-forward` to a runsc pod does not work —
  gVisor sockets live in netstack, not the kernel netns — so use the
  Service/pod-IP path, as the gateway does. The full matrix and the
  weekly CI re-proof are in `docs/compatibility.md`.
- Per-user session limits were not exercised by the v0.3.0 soak
  (60 sessions across 20 users) and the API still has no per-user
  limit store — `userLimits` is absent, quota is tenant-scoped.
- Server-originated free text is English only: the portal renders
  known event/condition `reason` tokens from the `en`/`vi` catalogs,
  but message parameters and unknown tokens arrive in English.
