# TinyCDI v1.2.0 — release notes (draft)

## Admin portal

- **Users page** (`/admin/users`): a tenant admin can now see every
  principal known to the tenant — the union of the admin quota view's
  `users[]` usage rows and the per-user limit rows — with running
  workspaces, the CPU/memory/storage usage vector, the running limit and
  its effective value, and the retained-disk count. A per-user detail page
  (`/admin/users/{subject}`) lists that user's workspaces and retained
  disks and reuses the per-user limit editor. No `/v1` API change; all
  reads are the existing tenant-admin endpoints.
- **Paginated, sortable tables.** The admin lists — workspaces, retained
  data, templates, users — and the personal retained-data list now page
  client-side (default 50 rows, selectable 25/50/100) and sort by column.

## Known limitations

- **The admin Users page is not a tenant directory.** `/admin/users` lists
  only principals who have used the tenant — a quota usage row or a
  per-user limit row. A user who has never held a workspace, retained disk
  or limit override does not appear. Listing every tenant member needs a
  future additive API (e.g. `GET /v1/admin/tenants/{tenant}/users` backed
  by the principal directory).
- **Client-side table paging.** Tables still read the whole list
  client-side (up to 4000 records, with the existing truncated notice
  beyond that); server-side paging/sort params remain a future additive
  `/v1` extension.
