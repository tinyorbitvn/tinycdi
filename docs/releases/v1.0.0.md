# TinyCDI v1.0.0 — release notes

v1.0.0 is the first stable release of TinyCDI. The product code is
identical to v0.5.1 — 1.0 adds the stability contract
(`docs/versioning.md`), the completed internal security review
(`docs/security/review-v1.0.md`) and the support policy
(`SECURITY.md`), not new features. Merged since v0.5.1: documentation
and release-process changes only. There is **no database migration and
no CRD change** — an install on v0.5.1 upgrades with a chart and image
bump alone.

## What 1.0 promises

From 1.0.0 the project versions by semver — breaking changes to the
stable surface mean a new major. The contract is `docs/versioning.md`;
in short:

- **Covered:** the `/v1` HTTP API as specified by the OpenAPI document
  (`internal/api/openapi.yaml`) — minors are additive only — the Helm
  chart values, which get a one-minor deprecation window before a value
  is removed or changes meaning, and the documented upgrade path
  (`docs/runbooks/upgrade.md`) between consecutive minors.
- **Not covered:** the `Workspace` and `WorkspaceTemplate` CRDs stay
  `v1alpha1` — they are the operator's internal contract, not a public
  API, and promotion with conversion is planned for a later release;
  the internal operator↔backend mTLS API; metric names and the
  log/audit field layout (kept stable on a best-effort basis only); and
  image internals — the documented contract in `docs/images.md` is what
  holds.

## Security

v1.0.0 ships with the completed internal security review —
`docs/security/review-v1.0.md` is the full report. Five read-only
review passes ran in parallel, one per trust-boundary group (auth and
session; session listener and gateway; control plane; data, tenancy
and operations; supply chain and CI) against the frozen v0.5.0 tree; a
second, adversarial pass reproduced or refuted every finding (33
filed, 33 confirmed); and the release-candidate end-to-end gates
doubled as the live-fire drills on a disposable install.

- **P0: 0.**
- **P1: 1, fixed** — a forged `template-snapshot` annotation could make
  the operator build pods from an arbitrary spec (#146, verified by the
  forged-annotation drill).
- **P2: 9** — 8 fixed; 1 open: the single-actor merge→publish path
  (SR-5-F2), a repository-governance decision pending the user.
- **P3: 22** — 16 fixed; 3 accepted with an owner and target v1.1 (the
  `ClusterOnly` egress posture, `extraEnv` vs the chart's render
  guards, per-certificate revocation on the internal mTLS hop); 3
  listed open (non-concurrent migration index builds, gate-failed
  digests pullable-by-digest, repository SHA-pinning enforcement — the
  last also a governance item).
- **1 duplicate record.**

All code fixes shipped in **v0.5.1** — `docs/releases/v0.5.1.md` has
the per-item detail. This was an **internal review by the project's
own workers, not an independent audit**; an external review and the
repository-governance hardening (a second-actor publish path,
platform-enforced SHA pinning) remain open items for the user to
decide.

## Support policy

Per `SECURITY.md`:

- The **latest 1.x minor** is fully supported — fixes ship as new patch
  releases on that line.
- The **0.5.x line** gets security fixes only (Critical/High) for 90
  days after the v1.0.0 final tag; no feature backports.
- **0.4 and older are unsupported** — upgrade.

Vulnerabilities are reported privately through GitHub's private
vulnerability reporting per `SECURITY.md`.

## The road to 1.0

- **v0.1** — the first public release: OIDC sign-in, per-workspace
  KasmVNC desktops and browsers streamed to the user's browser,
  workspace lifecycle and templates, signed images and chart.
- **v0.2** — the three-component architecture (backend, frontend,
  operator): sessions bound to Postgres leases survive restarts, one
  subdomain per workspace, retained home disks, tenant quotas, the
  runtime image train.
- **v0.3** — "Operate": template families with update policies,
  operator HA and mTLS hot reload, application rate limits, metrics,
  dashboards and alerts, a real XFCE desktop, the Kasm catalog gate.
  Patches added pod topology spread, session telemetry and
  `en`/`vi` reason catalogs, per-route Gateway chart options and the
  runtime manifest.
- **v0.4** — sign-out revokes the session's live streams and
  outstanding tickets (threat-model S17), exact aggregate rate limits
  via a Postgres-backed shared window (ADR 0006), structured localized
  event params.
- **v0.5** — "sign out everywhere" (ADR 0007), per-user
  running-workspace limits, one dedicated audit event per mutating and
  admin route, the verified Postgres-only-restore procedure with
  `backend post-restore`, intent drift surfaced as `IntentBehind`.
- **v0.5.1** — the security-review fix release: operator-authoritative
  template snapshots in `status.templateSnapshot`, plus hardening
  across the session listener, the gateway proxy, rate-limit keys,
  sign-out, the internal control API, the chart and the supply chain.

## Upgrading

The procedure is `docs/runbooks/upgrade.md`.

- **From v0.5.1:** a chart and image upgrade only — the CRDs are
  unchanged since v0.5.1 (`status.templateSnapshot` arrived there) and
  there is no migration; `helm upgrade` per the runbook.
- **From v0.5.0 or older:** do not jump straight to v1.0.0 — first
  follow `docs/releases/v0.5.1.md`, which carries a CRD apply and the
  one-time `Degraded`/`TemplateRevisionGone` hold on running
  workspaces, then move to v1.0.0.
- **Older than v0.5.0:** upgrade minor by minor per
  `docs/runbooks/upgrade.md`.

## Known limitations

The review's residual list (`docs/security/review-v1.0.md` §6) carries
into v1.0.0:

- **No per-certificate revocation on the internal mTLS hop** — no
  CRL/OCSP/serial blocklist: removing trust in one client certificate
  means rotating the client CA bundle, which drops every client.
  Short-lived certs via cert-manager remain the mitigation — rotation
  is the revocation mechanism. Accepted; target v1.1.
- **`extraEnv` vs the chart's render guards** — `denyExtraArgs`
  refuses the dangerous flags unless `dev.enabled`, but
  `<component>.extraEnv` renders verbatim and can carry the same
  flags' environment equivalents. Set `extraEnv` with the same care as
  the guarded flags; an env-name deny-list is the planned fix.
  Accepted; target v1.1.
- **`ClusterOnly` egress posture** — a `ClusterOnly` workspace may
  reach any pod that does not restrict its own ingress; the opt-in
  `runtime.networkProfiles.clusterOnly.egress*` values narrow egress
  to selector-matched peers. Accepted as documented posture.
- **Per-prefix rate budgets** — IPv6 client keys fold to the /64, but
  a client holding several /64s or several egress addresses gets a
  budget per prefix (per-prefix limiting as designed); the forwarded
  key derivation assumes every hop in front is in
  `-trusted-proxies`.
- **KasmVNC per-desktop upstream ceiling** — the runtime's own: in a
  measured burst of 100 simultaneous reconnects to one desktop, 65
  succeeded and 35 were answered `502` by the runtime, not by the
  gateway or the limiter — a single measurement, not a precise cap
  (`docs/runbooks/capacity.md`).
- **Server-side English reason strings** — the portal renders the
  known event/condition `reason` templates from the `en`/`vi`
  catalogs; unknown tokens and other server messages arrive in
  English.
- **Audit stream** — stdout JSONL: emission and shape are guaranteed;
  delivery, retention and tamper evidence are the operator's log
  pipeline.
- **Listed open items** — migrations 020/023 build indexes with
  non-concurrent `CREATE INDEX` inside the migration transaction (run
  that upgrade in a quiet window on large installs); a gate-failed,
  never-promoted image digest stays pullable-by-digest (the
  consumption contract is per-digest cosign verification per
  `docs/security/provenance.md`); DNS egress is allowed on every
  network profile including `Isolated` by design.
- **Watch item** — on one release-candidate rollout a desktop stream
  did not re-land within a 30 s observation window while its lease
  stayed live (it re-landed in ~1 s on a controlled re-run — a
  marginal retry-window edge, not reproduced). Watch for reports of
  mid-rollout stream loss and flag them if seen.
