# TinyCDI 1.0.0

TinyCDI is a Kubernetes-native platform for browser-delivered Linux
desktops and single-app browser workspaces. A platform team installs it on
its own Kubernetes cluster with one Helm chart and runs it there. A user
signs in to a web portal and opens a desktop or a browser workspace in a
browser tab with one click.

## Features

### For users

- **Portal.** Create, start, stop and delete workspaces from the
  templates your tenant offers. Each workspace keeps a persistent home
  volume, and retained data from a deleted workspace can be attached to a
  new one (`:attach`).
- **Desktop in the browser.** The desktop streams over KasmVNC behind an
  authenticating session gateway. Each workspace is served on its own host,
  `<label>.<sessionDomain>`.
- **Clipboard and file transfer** within the ceiling your tenant sets. File
  transfer moves one file at a time into and out of the `~/transfers`
  folder of the workspace, up to the platform's per-file cap.
- **Sign out everywhere.** One action ends every portal session you hold
  in the current tenant and revokes that tenant's live desktop connections
  and outstanding launch tickets. Sessions you hold in other tenants are
  not touched.

### For tenant admins

- **Overview** of the tenant's capacity and health.
- **Workspaces** across every user of the tenant.
- **Quota** and per-user limits.
- **Session policy**: the clipboard and file-transfer ceiling, with
  `:apply` to restart running workspaces whose policy is looser than the
  ceiling. A dry run lists them first, and workspaces with a live desktop
  session are skipped unless you include them.
- **Templates** and **retained data**.
- **Users**: the directory of everyone who has signed in to the tenant,
  their active sessions, and a per-user sign-out.
- **Audit log** viewer.

### For platform operators

- One Helm chart (`oci://ghcr.io/tinyorbitvn/charts/tinycdi`) with three
  components (backend, frontend, operator). PostgreSQL is the only state
  store. The CRDs are `workspaces.cdi.tinyorbit.vn/v1`.
- Internal mTLS between the operator and the backend's `:9443` listener,
  with per-certificate revocation
  ([ADR 0008](../adr/0008-mtls-cert-revocation.md)).
- `ClusterOnly` workspaces get restricted egress by default: pods in the
  managed namespaces only.
- Optional, off by default: an admission policy, Grafana dashboards and
  Prometheus alert rules. Prometheus metrics are served on their own
  ClusterIP Service when enabled.
- Audit events are persisted in PostgreSQL and pruned after a retention
  period (default 90 days,
  [ADR 0010](../adr/0010-audit-store-and-retention.md)).
- Signed images and a signed chart, with SBOM attestations. The chart pins
  every runtime image by digest.

## Install

- Requirements: [compatibility.md](../compatibility.md).
- Install the chart:

  ```bash
  helm install tinycdi oci://ghcr.io/tinyorbitvn/charts/tinycdi --version 1.0.0 \
    -n tinycdi-system -f my-values.yaml
  ```

  The full procedure is in the [install runbook](../runbooks/install.md).
  For a local trial on a throwaway cluster, run `hack/quickstart/up.sh`
  ([quickstart](../quickstart.md)).
- Images are published as
  `ghcr.io/tinyorbitvn/tinycdi-<image>@sha256:<digest>`, and the chart pins
  their digests. Verify them with the `cosign verify` command in
  [provenance.md](../security/provenance.md#verification-side-what-a-consumer-runs)
  before you deploy.
- This release has no upgrade path from any earlier build: install it
  fresh.

## Known limitations

- **In-pod trust (file transfer).** The workspace pod runs one container,
  `desktop`, as uid/gid 1000 with `fsGroup` 1000, and its Secret is mounted
  read-only at `/run/secrets/tcdi` with mode `0440`. So the workspace user
  can read every key of that Secret, `xfer-token` included. The in-pod
  helper `tcdi-xferd` runs as that same user in the same container, so the
  user can also stop it, or try to serve port 8443 of the workspace pod
  with a program of their own. The entrypoint polls the helper every 2
  seconds and restarts the container when its process exits; that narrows
  the window but does not close it. The in-pod checks (the token, and the
  helper's `TCDI_XFER_POLICY` / `TCDI_XFER_MAX_BYTES` floor) are therefore
  defense in depth, not the control. The checks that decide run outside
  the pod. Only the workspace owner can mint a grant, through the API with
  a session and a CSRF token, and a grant expires after 2 minutes. The
  gateway claims the grant through the broker (`Broker.ClaimTransfer`)
  before it contacts the pod. The claim checks the live lease, the
  principal, the runtime incarnation, the direction, one live transfer per
  workspace and the policy in force at that moment, and it writes the
  audit row in the same transaction. The gateway then caps the bytes it
  moves in either direction at the grant's size. Nothing in the pod's
  Secret lets it mint or claim a grant. Net effect: a tampered helper can
  mishandle only that workspace's own files, within the direction and size
  the claim allowed. See §5 of
  [ADR 0009](../adr/0009-session-data-transfer-policy.md).
- **File transfer scope.** One file at a time per workspace: a second claim
  while one stream is live is refused. Files are addressed by name in the
  flat folder `~/transfers`, and there is no listing. A download is held in
  the browser tab's memory, up to `maxFileBytes`. See
  [session-policy.md](../runbooks/session-policy.md#file-transfer).
- **KasmVNC under connection saturation.** The gateway caps live upstream
  connections per workspace per backend replica at
  `backend.sessionStreamCap` (default 32). Over the cap it answers `429`
  and the client retries. The cap is per replica, so N replicas admit
  N × cap. The image lowers KasmVNC's file-descriptor limit below
  `FD_SETSIZE`, so overload becomes `EMFILE` refusals. A direct burst far
  above the cap can still crash Xvnc and restart the container; that path
  is not reachable through the gateway. See the threat-model row
  "Reconnect storm could crash a workspace runtime (KasmVNC fd bound)" in
  [threat-model.md](../security/threat-model.md).
- **mTLS revocation is server-side only.** The backend's internal mTLS
  listener (`:9443`) rejects client certificates whose serial is on the
  blocklist. The internal client (the operator) does not check the server
  certificate's serial. See
  [ADR 0008](../adr/0008-mtls-cert-revocation.md).
- **Revocation records are not pruned.** Each revoked workspace runtime
  generation adds one `workspace_revocation` row, and no job deletes these
  rows. The table is small, but it grows. See
  [ADR 0003](../adr/0003-gateway-broker-internal-api.md), which describes
  the row.
- **Some audit events are stdout-only.** Every audited API route and the
  file-transfer claim and completion are stored in PostgreSQL. These go to
  the log stream only: the gateway's events (`launch.redeem`,
  `launch.host_mismatch`, `session.lookup`, `session.stream`,
  `session.list`, `session.revoke`, `session.host_mismatch`),
  `session.touch`, the per-request `http.request` record, the sign-out
  `session.revoke` record and `admin.quota.config_apply`. Delivery,
  retention and tamper evidence for the log stream are the operator's
  responsibility. See
  [ADR 0010](../adr/0010-audit-store-and-retention.md),
  [audit.md](../runbooks/audit.md) and
  [observability.md](../runbooks/observability.md#log-integrity--what-tinycdi-guarantees-vs-what-you-must-provide).
- **Rate-limit budgets are per client address.** The sign-in and launch
  budgets key on the client IP (behind trusted proxies, the right-most
  untrusted `X-Forwarded-For` entry), with IPv6 folded to its /64. A client
  that holds many addresses or /64 prefixes gets one budget per address or
  prefix. See [ADR 0006](../adr/0006-rate-limit-state.md) and
  [capacity.md](../runbooks/capacity.md#sign-in-rate-limits-and-nat).
- **DNS egress is open on every network profile.** Every workspace
  NetworkPolicy allows UDP and TCP 53 to the cluster DNS pods
  (`k8s-app: kube-dns`), `Isolated` included: for `Isolated` it is the only
  egress. Whether names outside the cluster resolve depends on the cluster
  DNS configuration. See
  [the chart README](../../deploy/helm/tinycdi/README.md#clusteronly-egress).
- **Node drain loses running desktops.** A Ready workspace whose pod is
  deleted, evicted or failed goes `Failed` with reason `RuntimeLost` and is
  not rebuilt automatically. The owner or an admin presses Start, which
  starts a new runtime generation on the same home volume. See
  [lifecycle-reasons.md](../lifecycle-reasons.md).
- **The admin user directory lists signed-in users only.** It lists
  everyone who has signed in to the tenant; users who have never signed in
  are not listed. The session list shows live leases only, not past
  sessions; past sign-ins are in the audit log. See
  [tenant-quotas.md](../runbooks/tenant-quotas.md).
- **Failed-digest cleanup is check-then-act.** When the release pipeline
  deletes the image versions of a run that failed its gates, a version
  could gain a tag or a referrer between the check and the deletion. See
  [provenance.md](../security/provenance.md).
- **Browser support.** Safari/WebKit is out of scope (see
  [compatibility.md](../compatibility.md)). The browser images install
  their browsers from apt with pinned versions, and the pins need
  repinning when Debian security updates supersede them (see
  [images.md](../images.md#known-limitations)).
- **Single maintainer, no independent audit.** The same account can
  author, merge and approve a publish; the recorded `release` and
  `runtime-train` environment approvals are the control. No independent
  security audit has been done. See [SECURITY.md](../../SECURITY.md) and
  [provenance.md](../security/provenance.md#what-a-signature-does-not-prove).

- Report a vulnerability as described in [SECURITY.md](../../SECURITY.md).
