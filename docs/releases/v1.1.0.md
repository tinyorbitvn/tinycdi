# TinyCDI v1.1.0 — release notes (draft)

## `<component>.extraEnv` refuses dev-surface and chart-managed env names (SR-3-F2)

`<component>.extraEnv` rendered verbatim — after the chart's managed env
block — so it carried the environment equivalents of the flags the chart
pins closed, and a duplicate of a chart-managed name silently won. The
render now **fails** (the error names the component and the env var) when
`dev.enabled` is false and an `extraEnv` entry's name is either:

- a dev-surface env name — `TCDI_DEV_INSECURE_DB`,
  `TCDI_DEV_ALLOW_NO_BROKER`, `TCDI_METRICS_LISTEN`,
  `TCDI_KASM_ADAPTER_IMAGE`, `PGSSLMODE`, `TCDI_OPERATOR_CN`,
  `TCDI_WATCH_NAMESPACES`, `TCDI_REQUIRED_GROUPS`; or
- an env var the chart itself manages for that component (e.g.
  `TCDI_DATABASE_URL`, `TCDI_OIDC_*`, `TCDI_TENANT_*`, `POD_NAMESPACE`,
  `SSL_CERT_FILE`).

**Upgrade impact:** an operator carrying one of these names in `extraEnv`
now gets a render error instead of a silently-weakened install. Set the
corresponding chart value instead (e.g. `database.tls.mode` for
`PGSSLMODE`, `managedNamespaces` for `TCDI_WATCH_NAMESPACES`), or — for
development only — set `dev.enabled: true`, which keeps the escape
hatch. Non-listed `extraEnv` names render unchanged.
