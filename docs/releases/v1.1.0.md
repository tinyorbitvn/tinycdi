# TinyCDI v1.1.0 — release notes (draft)

## `<component>.extraEnv` refuses dev-surface and chart-managed env names (SR-3-F2)

`<component>.extraEnv` rendered verbatim — after the chart's managed env
block — so it carried the environment equivalents of the flags the chart
pins closed, plus the env names of security-relevant flags the chart
exposes as first-class values (live whenever the flag is not rendered),
and a duplicate of a chart-managed name silently won. The render now
**fails** — the error names the component, the env var and the value to
set instead — when `dev.enabled` is false and an `extraEnv` entry's name
is either:

| Denied `extraEnv` name | Set instead |
|---|---|
| `TCDI_DEV_INSECURE_DB` / `PGSSLMODE` | `database.tls.mode` (verify-ca/verify-full) |
| `TCDI_DEV_ALLOW_NO_BROKER` | `operator.devAllowNoBroker` (dev-only) |
| `TCDI_METRICS_LISTEN` | `backend.metrics.enabled` |
| `TCDI_KASM_ADAPTER_IMAGE` | `kasmAdapter.enabled` + `kasmAdapter.image.digest` |
| `TCDI_OPERATOR_CN` | `backend.operatorCN` |
| `TCDI_WATCH_NAMESPACES` | `managedNamespaces` |
| `TCDI_REQUIRED_GROUPS` | `oidc.requiredGroups` |
| `TCDI_CONTROL_TOKEN` / `TCDI_GW_CONTROL_TOKEN` / `TCDI_CONTROL_TOKEN_FILE` | `backend.controlToken.existingSecret` |
| `TCDI_TRUSTED_PROXIES` | `backend.trustedProxies` |
| `TCDI_UPSTREAM_CA` | `backend.upstreamCA.existingSecret` |
| `TCDI_OIDC_POST_LOGOUT_REDIRECT` | `oidc.postLogoutRedirect` |
| `TCDI_TENANT_QUOTAS` | `managedNamespaces[].quota` |

- or an env var the chart itself manages for that component (e.g.
  `TCDI_DATABASE_URL`, `TCDI_OIDC_*`, `TCDI_TENANT_*`, `POD_NAMESPACE`,
  `SSL_CERT_FILE`) — a duplicate later in the env list would silently
  win. Non-map or nameless `extraEnv` entries fail the render too.

**Upgrade impact:** an operator carrying one of these names in `extraEnv`
now gets a render error instead of a silently-weakened install — set the
corresponding chart value per the table, or — for development only — set
`dev.enabled: true`, which keeps the escape hatch. Non-listed `extraEnv`
names render unchanged.

## Internal mTLS: per-certificate revocation (SR-3-F5, ADR 0009)

The internal broker listener (`:9443`) gains an opt-in serial blocklist.
Today, distrusting one compromised operator or gateway client certificate
meant rotating the client-CA bundle, which drops every client of the
listener at once. With the new backend flag `-internal-revoked-list`
(env `TCDI_INTERNAL_REVOKED_LIST`) or the chart value
`backend.tls.internal.revokedSerials.existingSecret`, a mounted Secret
carries the revoked `(issuer, serial)` pairs; a listed leaf's TLS
handshake is aborted — including on resumed sessions — and its
established connections are severed on the same reload pass. The list
hot-reloads on the proven poll+hash path (~90 s propagation worst case),
keeps the last-good list on a bad read, and fails closed at boot when the
flag is set but the file is unusable.

- New metrics: `tinycdi_internal_mtls_revoked_serial_total{listener}`,
  `tinycdi_internal_mtls_revocation_entries`,
  `tinycdi_internal_mtls_revocation_reload_errors_total`, plus the
  rate-limited `internal_mtls_revoked_cert` WARN line.
- Contract impact: none on `/v1` — the check is at the TLS layer, below
  HTTP. Chart values are additive with safe defaults; the default render
  is byte-identical (feature off). Runbook:
  `docs/runbooks/mtls-cert-revocation.md`.
