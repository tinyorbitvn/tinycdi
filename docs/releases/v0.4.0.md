# TinyCDI v0.4 — release notes (in progress)

**Status: Unreleased.** v0.4 is a minor release on the v0.3 line:
additive public API changes and portal improvements. Sections are
appended per merged change ahead of the v0.4.0 tag.

## What is new

**API and portal**

- Structured `params` on workspace events and conditions (B3-PARAMS):
  `WorkspaceEvent` and `WorkspaceCondition` may now carry `params`, a flat
  string map with the values the `reason`'s message interpolates —
  intent `revision`, stop `cause`, guard `skipReason`, the producing
  `condition`/`status`, the teardown `step` and the drain `budgetSeconds`
  (the full table is in `docs/lifecycle-reasons.md`). The portal renders
  its `en`/`vi` reason templates with these values localized —
  `TemplateUpdateSkipped` now reads e.g. "Workspace giữ nguyên revision
  template đã ghi nhận 7 (dung lượng nhỏ hơn)." instead of appending the
  English detail — and falls back to the server `message` when a token or
  a param is unknown, exactly as v0.3.x did. Stop intents recorded with an
  `idle_timeout`/`disconnect_timeout` cause now surface as their own
  `IdleTimeout`/`DisconnectTimeout` event reasons (previously a generic
  `StopRequested`). Additive only: `params` is optional everywhere, so
  mixed v0.3.x/v0.4 deployments degrade to the v0.3 rendering.

## Upgrading from v0.3.x

- Behaviour change (advisor-accepted): stop events recorded for
  `idle_timeout`/`disconnect_timeout` causes now carry the reason
  `IdleTimeout`/`DisconnectTimeout` instead of `StopRequested`; their
  event ids change accordingly — clients grouping by `reason` should add
  the new tokens. The recorded `cause` is still carried in
  `params.cause`, so the `StopRequested` + cause detail is not lost.
- `params` on `WorkspaceEvent`/`WorkspaceCondition` is optional and
  additive: older clients ignore it and v0.3.x replicas interoperate
  unchanged; the operator-side condition-params annotation is metadata
  only, so no CRD or migration is needed.
